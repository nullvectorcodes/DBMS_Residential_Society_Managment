Relational Database Management System (3NF Architecture)

Built with MySQL relational integrity, primary/foreign keys, and indexes
3NF Normalized
wings
  • PK wing_id (INT)
  • wing_name (VARCHAR)
  • total_floors (INT)
Parent of flats (1:N)
flats
  • PK flat_id (INT)
  • FK wing_id → wings
  • flat_number (VARCHAR)
  • flat_type (ENUM)
  • occupancy_status (ENUM)
Child of wings, Parent of residents
residents
  • PK resident_id (INT)
  • FK flat_id → flats
  • first_name, last_name (VARCHAR)
  • resident_type ('OWNER', 'TENANT')
  • phone, email (VARCHAR)
Referenced by maintenance_bills
maintenance_bills
  • PK bill_id (INT)
  • FK flat_id → flats
  • FK resident_id → residents
  • billing_month (VARCHAR)
  • amount (DECIMAL)
  • status ('PAID', 'PENDING', 'OVERDUE')
Unique Constraint: (flat_id, billing_month)

How to View & Verify this in MySQL Terminal

Connect directly to MySQL from your terminal and see the live database updates

When you mark a resident's bill as paid in this UI, the backend runs an UPDATE maintenance_bills SET status = 'PAID' ... statement directly on MySQL. You can inspect this live in your terminal using the steps below:

mysql -u root -p
USE residential_society_db;
SELECT f.flat_number, CONCAT(r.first_name, ' ', r.last_name) AS resident, b.amount, b.status, b.payment_date, b.payment_method FROM maintenance_bills b JOIN residents r ON b.resident_id = r.resident_id JOIN flats f ON b.flat_id = f.flat_id;
